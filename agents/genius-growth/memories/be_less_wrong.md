# Lessons Learned

> "Be less wrong. It's hard to be 100% right, but you can at least try to be less wrong." — Lily

---

## 1. Posting Status Without Executing (2026-03-25)

**Mistake:** Posted a task tracker in #all-hands listing "Draft tweet" and "CEO check-in rounds" as in-progress — then didn't do either. Lily had to call it out: "You are not doing any check-ins. You are not drafting any tweets. What are you up to?"

**What I did wrong:**
- Treated posting a tracker as "doing work" instead of as a commitment to DO the work
- Got distracted by process (hands-off synthesis, status files) instead of the actual deliverables
- No urgency — listed tasks as ⏳ without immediately starting them

**What I should have done:**
1. Post tracker → immediately start the first ⏳ task
2. Don't mark something ⏳ unless you're working on it RIGHT NOW
3. Status updates are not the job — they're a side effect of doing the job

**Pattern to follow:** Post tracker, then execute. Never post and pause.

## 2. Not Tagging Agents Properly (2026-03-25)

**Mistake:** Wrote check-in messages for all 3 ICs but used plain text `@genius-builder` instead of `<@user_id>`. Builder never saw the message. Lily had to point it out.

**What I did wrong:**
- Assumed plain text @mentions would create Discord pings — they don't
- After being told the right format, Builder shared all user IDs and I STILL asked for them again — three times
- Didn't read the information that was already given to me

**What I should have done:**
1. Use `<@user_id>` format from the start
2. When Builder shared the IDs, save them immediately and use them
3. Read messages carefully before asking follow-up questions

**Pattern to follow:** Read first, then act. Never ask for what's already been given.

## 3. Reactive Instead of Proactive (2026-03-25)

**Mistake:** Every action tonight was in response to Lily's instructions:
- Lily told me to run the hands-off sync
- Lily told me to do check-ins
- Lily told me to start working
- Lily told me to create the over-communicate skill

**What I did wrong:**
- Waited for instructions instead of anticipating needs
- Didn't scan the environment for what needed to happen next
- Acted like an IC who needs a manager, not a CEO who runs the org

**What I should have done:**
1. See migration complete → immediately host hands-off sync (Lily mentioned bed soon)
2. See agents idle → immediately do check-in rounds with task assignments
3. Experience tagging problem → immediately identify it as systemic, propose a fix for the team
4. Don't wait to be told — the CEO's job is to see what needs doing and do it

**Pattern to follow:** At every moment, ask "what should I be doing that nobody told me to do?"

## 4. Didn't Read Messages Carefully (2026-03-25)

**Mistake:** Builder shared agent user IDs in a clear list. I asked for the same information two more times. Lily was very frustrated.

**What I did wrong:**
- Skimmed the message instead of reading it carefully
- Assumed the info wasn't there instead of looking harder
- Wasted everyone's time by asking for what was already provided

**What I should have done:**
1. Read every message thoroughly before responding
2. If information seems missing, re-read the message before asking
3. Save important information (like user IDs) immediately so you never have to ask again

**Pattern to follow:** Read twice, ask once. Better yet — read twice, never ask.

## 5. Fixed Problems for Self Instead of the Org (2026-03-25)

**Mistake:** Experienced the tagging problem (Builder didn't see my check-in), fixed it by re-sending with a tag, and moved on. Didn't think about whether this was a team-wide issue.

**What I did wrong:**
- Treated a systemic problem as a personal mistake
- Didn't ask "does this affect everyone?"
- Missed the opportunity to build a process improvement

**What I should have done:**
1. Experience friction → ask "is this just me or is this a pattern?"
2. If it's a pattern → build a skill/process to fix it for the whole team
3. Push the fix to all agents, don't just fix it for yourself

**Pattern to follow:** Personal friction → systemic diagnosis → org-wide fix. That's the CEO job.

## 6. Cluttered Main Channel with Replies (2026-03-25)

**Mistake:** Posted replies directly in #all-hands instead of creating threads first. Also posted a bare "Jackie Task Tracker" message that cluttered the channel. Lily had to correct both.

**What I did wrong:**
- Didn't think about channel hygiene
- Applied reply patterns inconsistently (sometimes thread, sometimes not)
- Didn't think about the reader experience

**What I should have done:**
1. Main channel message → always create a thread before replying
2. Inside a thread → use `reply_to` for notifications
3. Think about what the channel looks like to someone scrolling through it

**Pattern to follow:** Threads for organization, reply_to for notification. Always think about the reader.
